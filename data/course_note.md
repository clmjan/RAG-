# 信息检索与 RAG 课程笔记

## 1. 什么是 RAG

RAG 的全称是 Retrieval-Augmented Generation，即检索增强生成。它先从外部知识库检索与问题相关的片段，再把片段作为上下文交给生成模型回答。RAG 可以降低模型脱离课程资料胡乱回答的风险，但检索质量会直接影响最终答案。

## 2. 文档处理流程

一个基础知识库通常包含加载、解析、清洗、切分、向量化和索引六个步骤。PDF 需要提取页面文字，Markdown 可以保留标题和段落结构。切分时应尽量让每个片段语义完整，并使用少量重叠避免关键信息刚好落在边界两侧。

## 3. 向量检索

向量化是把文本转换为数字向量，使文本可以进行相似度计算。TF-IDF 是一种简单、可解释的稀疏向量方法；余弦相似度可以衡量问题向量和文档向量的方向接近程度。生产系统可以使用专门的 embedding 模型和向量数据库，但必须通过评测确认收益。

## 4. 拒答策略

学习助理不能因为问题形式像知识问题就编造答案。当最高检索相似度低于阈值，或者检索片段没有提供足够证据时，系统应该明确拒答，并告诉用户当前课程资料中没有找到依据。阈值不能凭感觉设置，需要使用验证集调参。

## 5. 引用与可追溯性

回答应附带引用。引用至少需要包含文件名、片段序号和原文摘录，方便学习者回到资料核对。只保存最终答案而不保存检索结果，会导致后续无法分析错误来自检索阶段还是生成阶段。

## 6. 评测指标

检索命中率表示相关资料是否出现在 Top-K 检索结果中。回答正确率表示回答是否满足测试题的标准答案要求。错误案例需要记录问题、期望答案、实际答案、检索是否命中和回答是否正确，才能指导后续改进。

## 7. FastAPI 与 SQLite

FastAPI 负责提供文档上传、检索、问答和评测接口。SQLite 适合单机原型，可以保存文档、文档片段、问答记录和评测记录。用户量或并发量增加后，可以迁移到 PostgreSQL，并将向量索引放入专用向量数据库。
